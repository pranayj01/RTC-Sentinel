# End-to-end browser testing

Phase 14 uses Playwright to test RTC Sentinel through the same Nginx, Express, Socket.IO, FastAPI, PostgreSQL, Redis, and Coturn services used by the running application.

## Covered flow

The Chromium test creates two isolated browser contexts and grants microphone permission to both. It then:

1. Creates unique host and participant accounts through the public registration API.
2. Signs both users in through the visible React interface.
3. Creates a room in the host browser and joins it in the participant browser.
4. Waits for both browsers to report a connected `RTCPeerConnection`, proving SDP negotiation and ICE exchange completed.
5. Verifies signaling automatically created the PostgreSQL call and advanced it to `CONNECTED`, without calling the call-lifecycle REST write endpoints.
6. Waits for a real `getStats()` RTT sample generated by Chromium's fake audio device.
7. Verifies at least one QoS record was stored for the connected call in PostgreSQL.
8. Ends the call, confirms the other participant observes the departure, and verifies the persisted record automatically reaches `ENDED` with an end time and duration.

A second Chromium test enables `?relay=1`, signs in one host, joins a second
browser anonymously, and requires both peers to connect with `Network Path:
RELAY`. This exercises Coturn allocation and media relay rather than merely
checking that ICE configuration exists.

The tests use fake microphone input, but they do not mock `RTCPeerConnection`, Socket.IO, HTTP, Redis, Prisma, PostgreSQL, or Coturn. They intentionally test the integrated call path rather than WebRTC browser internals already owned by Chromium.

## Run locally

Start and health-check the complete system:

```bash
docker compose up --build --wait
```

Install the managed browser once, then run the headless suite:

```bash
npx playwright install chromium
npm run test:e2e
```

To watch the two browser sessions:

```bash
npm run test:e2e:headed
```

Set `E2E_BASE_URL` to test a different deployment. The default is `http://localhost:5173`.

## Failure artifacts

Failed runs retain an HTML report, screenshots, video, and a Playwright trace in ignored local directories. Open the report with:

```bash
npx playwright show-report
```

The GitHub Actions workflow installs Chromium and its Linux dependencies, starts the Compose stack, runs service smoke tests, runs the Playwright flow with one worker, and always tears down the containers and volumes.

## Test data

Accounts use unique timestamped email addresses, so repeated local runs do not collide. Call and metric rows remain in the local PostgreSQL volume for inspection. Run `docker compose down --volumes` only when you intentionally want to remove all local development data.
